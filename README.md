# Конвертер валют — MAUI + собственный сервер

Учебное решение для Visual Studio 2022. Android, Windows, iOS и macOS (Mac Catalyst).
Используется .NET SDK 9.0.318, MAUI 9.0.120, CommunityToolkit.Mvvm 8.4.2.
Версия .NET выбрана для совместимости с уже установленной Visual Studio 2022.

## Состав решения

- `CurrencyConverter2` — общий интерфейс XAML и платформенные реализации хранения/настроек.
- `CurrencyConverter.Core` — модели, ViewModel, интерфейсы сервисов, HTTP-клиент своего сервера; не зависит от MAUI.
- `CurrencyConverter.Server` — ASP.NET Core API, получение и кеширование ответов cbr-xml-daily.ru.
- `CurrencyConverter.Tests` — unit-тесты ViewModel и серверного кеша на xUnit.
- `CODE_EXPLANATION.md` — подробное объяснение архитектуры и построчный разбор исходников.
- `.github/workflows/build.yml` — тесты, сборка сервера и четырёх платформ. В GitHub ничего не опубликовано.

## Первый запуск в Visual Studio 2022

1. Откройте `CurrencyConverter2.sln`. Требуется Visual Studio 2022 17.12+ с компонентами .NET MAUI и ASP.NET.
2. Дождитесь восстановления NuGet-пакетов. Не обновляйте MAUI до 10 при сохранении целевых платформ .NET 9.
3. Запустите `CurrencyConverter.Server` без отладки (контекстное меню проекта → Отладка → Запуск без отладки).
   Адрес сервера: `http://localhost:5080`; проверка: `http://localhost:5080/health`.
4. Выберите `CurrencyConverter2` запускаемым проектом, затем Pixel 7 / Android 12 и нажмите F5.
5. На Android-эмуляторе уже указан адрес `http://10.0.2.2:5080/`: это адрес компьютера-хоста со стороны эмулятора.
   Для Windows используется `http://localhost:5080/`.

В VS 2022 17.11+ также можно выбрать профиль **«Сервер и приложение»** из `CurrencyConverter2.slnLaunch`.
При необходимости включите multi-project launch profiles в настройках VS или задайте в свойствах решения
несколько запускаемых проектов: сначала Server, затем App. Если сервер уже запущен, второй экземпляр запускать не нужно.

Для запуска через командную строку из корня решения:

```powershell
dotnet run --project src/CurrencyConverter.Server
dotnet build CurrencyConverter2 -f net9.0-android -p:BuildTarget=net9.0-android
dotnet test tests/CurrencyConverter.Tests
```

`BuildTarget` ограничивает сборку MAUI одной платформой и не меняет целевую платформу библиотеки Core.
Для Windows: `-f net9.0-windows10.0.19041.0 -p:BuildTarget=net9.0-windows10.0.19041.0`.
Полная сборка приложения для Apple требует Mac с подходящим Xcode; Windows сам по себе не может собрать iOS/macOS.

## Использование

Выберите дату. Курсы загрузятся автоматически. Если на эту дату данных нет, сервер проверяет предыдущие дни,
а интерфейс показывает фактическую дату найденного курса. Для защиты от сотен запросов поиск ограничен 31 днём назад.
Поддерживаемый диапазон выбора — с 01.01.1999 по текущую дату; реальная доступность архива зависит от источника.
Если источник недоступен, ошибка сети не выдаётся за отсутствие курсов на конкретную дату.

Выберите валюты и введите сумму слева или справа: второе поле пересчитается автоматически.
Разрешены десятичная точка и запятая, ноль. Отрицательные суммы и разделители тысяч не принимаются.
Результат выводится максимум с 8 знаками после запятой. Для расчётов используется `decimal`.

Номинал учитывается: если источник передал стоимость 100 иен, сначала вычисляется стоимость одной иены.
Формула: **результат = сумма × (Value исходной / Nominal исходной) / (Value целевой / Nominal целевой)**.
Для RUB добавляется курс 1 рубль за 1 рубль.

Приложение автоматически сохраняет выбранную дату, обе валюты, обе суммы, направление последнего ввода и курсы.
При повторном запуске без сети можно пересчитывать по последнему сохранённому набору; его дата явно видна.
При первом запуске без сети вымышленные курсы не подставляются.

## Собственный сервер и кеш

Клиент вызывает только `GET /api/rates?date=yyyy-MM-dd` собственного сервера.
Только сервер обращается к `https://www.cbr-xml-daily.ru/archive/yyyy/MM/dd/daily_json.js`.
Ответ содержит `requestedDate`, `effectiveDate` и список валют с названием, кодом, номиналом и стоимостью в RUB.

Кеш двухуровневый: память + `src/CurrencyConverter.Server/App_Data/rates-cache/*.json`.
После перезапуска сервера дисковый кеш читается снова. Для старых найденных курсов срок хранения — 365 дней;
для свежих курсов и отсутствующих дат (404) — 30 минут. При необходимости уточнённые архивные курсы
можно получить после удаления соответствующего файла кеша и перезапуска сервера.
`SemaphoreSlim` объединяет одновременные обращения: один запрос к источнику заполняет кеш, остальные читают результат.
Запись JSON выполняется во временный файл с последующим переименованием.

Только 404 означает «на этот день данных нет»; ошибки 500, тайм-ауты и некорректный JSON считаются ошибками источника.
API возвращает 400 для неверной даты, 404 при исчерпании поиска, 502 при сбое источника, 504 при тайм-ауте поиска.
Сервер использует московскую текущую дату (UTC+3), поскольку курсы относятся к календарю источника.

## Реальное устройство и размещение сервера

На физическом телефоне `localhost` относится к самому телефону, а `10.0.2.2` работает только в Android-эмуляторе.
Разместите сервер на своём хостинге с HTTPS и укажите его адрес через меню «⋮» → «Адрес сервера».
В приложении HTTP разрешён только для локальных адресов разработки; проверка сертификатов HTTPS не отключается.
У iOS/Mac Catalyst включён доступ к локальной сети в ATS для разработки.
При развёртывании сервер может работать за HTTPS reverse proxy. Dockerfile запускается из корня решения:

```sh
docker build -f src/CurrencyConverter.Server/Dockerfile -t currency-server .
docker run --rm -p 5080:8080 -v currency-cache:/app/App_Data currency-server
```

Этот пример открывает HTTP-порт сервера локально. HTTPS для реальных устройств настраивается на хостинге/reverse proxy.

## Unit-тесты и GitHub Actions

Тесты не зависят от интернета: `IRatesService`, `IStateStore` и HTTP-ответы подменяются тестовыми реализациями.
Проверяются оба направления, номинал, смена валют, пустой/неверный ввод, сохранение/восстановление,
offline-режим, поздние ответы, CanExecute, поиск предыдущей даты, кеш на диске и в памяти, одновременные запросы.

После загрузки **содержимого этой папки** в корень репозитория workflow запускается на push, pull request и вручную.
Сначала выполняются тесты и публикация сервера. Только после успешных тестов строятся Android, Windows, iOS Simulator и Mac Catalyst.
Результаты тестов TRX и сборки доступны в разделе Actions → Artifacts.
Apple-сборка использует `macos-26`, Xcode 26.5 и workload set 9.0.314.3; версии согласованы по документации Microsoft.
Это учебные Debug-сборки, не публикация в магазины: для App Store/Google Play нужны собственные подписи и настройки публикации.
Фактический запуск workflow в GitHub не выполнялся: пользователь разместит проект самостоятельно.
